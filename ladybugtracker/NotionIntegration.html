Notion

Notion is a workspace and documentation service whose databases can be used as an issue tracker. LadyBug Tracker treats a Notion database as the project and each page inside it as an issue.

This integration is currently in the beta stage.

Authentication

Notion does not use a user name and password. It authenticates with an internal integration secret:

  1. Go to https://www.notion.so/my-integrations and create a new internal integration. The **Create Integration** button in the login window opens that page.
  2. Copy its secret into the Internal Integration Secret field in the login window.
  3. Open the database you want to use, and share it with that integration (Share menu > select your integration).

Step 3 is essential. Until the database is shared with the integration it is invisible to the API, and Notion reports it as not found rather than as forbidden — so a missing share looks like a wrong database name.

The host address is fixed to https://www.notion.so. The integration secret is already scoped to one workspace.

Project setup (Notion service)

Project selects the database by its title.

Notion database properties are user defined, so the plugin matches them to its own fields by name and type. Properties that are missing are simply not offered as fields, and the project verification reports which ones were not found instead of failing. The mapping is:

Level and Camera are the two properties LadyBug Tracker uses to store where a bug was reported from; add them as Text properties for 3D markers and the Goto button to work.

Created and Updated come from the page's own timestamps and are always available.

Integration capabilities

Notion never reports which capabilities an integration was granted, so the plugin probes them and shows the result in the settings window.

Comment reading is off by default in Notion. Without it the plugin skips reading comments rather than failing the whole fetch, so fields and attachments still load. To enable it, open the integration at notion.so/my-integrations and grant the read comments capability.

Attachments

Attachments are stored as blocks in the page body (image, video, audio, pdf or file), not in a files property. Appending never rewrites existing blocks, so a concurrent edit cannot drop earlier attachments.

Free Notion workspaces reject a file larger than 5 MB. Consider setting Max Screenshot Size in the project settings so large captures are downscaled before upload.

Subtasks

The subtask checklist is built from the to-do blocks of the page body. A Notion page has no checklist container, so all of its to-do items form a single checklist named Subtasks. Items can be added, renamed, ticked and removed; the checklist itself cannot be created or deleted.

Known limitations

  • Comments can be created and read, but the Notion API cannot delete them.
  • Issue history and workflow status transitions are not supported.
  • Creating a new database from the plugin is not possible, because the API cannot choose a parent page. Create the database in Notion first.
  • Deleting an issue archives the page, which is what Notion exposes instead of a hard delete.
  • A plain select property carries no completion information; use a status property if completion state matters.

Project setup (Unreal Engine)

Open Project Settings > Plugins > LadyBug Tracker and set:

  1. Provider — Notion.
  2. Host — leave at https://www.notion.so.
  3. Change Login Settings — paste the internal integration secret.
  4. Project — pick the database you shared with the integration.

These settings are stored in Config/DefaultBugTracker.ini and can be shared with the team. The integration secret is stored separately, per user, and only when Remember Me is enabled.
